Lo primero: entender el problema

📄 El enunciado

"Diseñar y construir un sistema simple de gestión de proyectos para una operación como la de Aztec."

Requisitos: CRUD, responsable, estado, prioridad, fecha límite, bloqueos, notas, detección de riesgos, vista operativa, criterio de priorización

📊 El dataset

Tres pestañas en un Excel: Projects, Tasks, Team. 22 proyectos reales con distintos estados, valores y niveles de urgencia.

13 bloqueados 4 en riesgo 5 sanos 85+ tareas

El reto no era técnico. Era de criterio: cómo priorizar, cómo estructurar, cómo hacer útil un sistema con datos reales.

Paso 3

¿Qué construir primero?

Frente a 24h, prioricé por impacto visible y dependencias:

1
Tipos + seed data — Sin datos no hay sistema. Primero modelar las entidades y cargar el Excel.

Decisiones de arquitectura

  • Server Components para layout y navegación
  • Client Components + useProjectStore para datos
  • localStorage como capa de persistencia
  • Seed data se carga en localStorage al primer inicio
  • Dominio aislado: todo lo de projects vive bajo src/domains/projects/
  • Sin backend: deploy directo en Vercel sin BD
Paso 5

Cómo funciona la persistencia

// src/domains/projects/hooks/use-project-store.ts

"use client";
import { useEffect, useState } from "react";

export function useProjectStore() {
  const [projects, setP] = useState<Project[]>([]);

  useEffect(() ⇒ {
    // Seed localStorage al iniciar
    if (!localStorage.getItem("aztec_projects"))
      localStorage.setItem("aztec_projects",
        JSON.stringify(seedProjects));
    setP(JSON.parse(...));
  }, []);

  return { projects, createProject, updateProject, ... };
}

El hook useProjectStore se usa en todos los componentes cliente. Almacena en localStorage, por lo que los datos persisten entre recargas y sesiones. Ideal para deploy en Vercel sin backend.

UX

Interactividad del lado cliente

La tabla de proyectos es el componente más interactivo. Usé useState + useMemo para eficiencia.

✅ Ordenamiento por columnas

Click en cualquier header (Código, Proyecto, Salud, Valor, Tareas, Prioridad). Segunda click invierte el orden.

✅ Filtros por salud

Chips: Todos / Bloqueados / En Riesgo / Sanos. Cada uno con contador. Sin recarga de página.

✅ Búsqueda en vivo

Filtra por nombre de proyecto, cliente, responsable o código. Resultados en tiempo real.

✅ Prioridad visual

Barra de progreso + score numérico. Colores semánticos: rojo (crítico), ámbar (alto), verde (bajo).

Todo client-side con useMemo. Sin llamadas al servidor. La data se filtra y ordena en el navegador.

Cierre

Decisiones conscientes

✅ localStorage vs BD

Para el prototipo alcanza. Seeds datos en localStorage al iniciar, persiste entre recargas. Producción iría con PostgreSQL + Prisma. La abstracción del hook permite cambiar el backend sin tocar la UI.

✅ Sin autenticación

Consciente. NextAuth.js o Clerk se agregan en producción. No aportaba valor al ejercicio de criterio operativo.

✅ Tests E2E > Unitarios

Preferí Playwright para probar flujos completos (7 tests) sobre tests unitarios del motor. El motor de priorización merece tests con Jest como siguiente paso.

✅ Diseño AztecLab

Tomé los colores, tipografía y estilo visual del sitio real de Aztec. Light mode, verde #6edd62, Plus Jakarta Sans.
